Why multi-agent coding breaks down

RUN 3+ INDEPENDENT HARNESS ON ONE REPO AND FIND OUT
01

Silent overwrites

Agent A refactors the frontend while Agent B rewrites the same files. Both report success. The `git push` decides who lost work.

02

Context blindness

Neither harness knows the other is even running — no shared roster, no scopes, no peek at the neighbor's plan until it conflicts.

03

No consensus

Breaking schema and contract changes land on trunk with no quorum, no peer verification, and no cryptographic receipt of who agreed.

04

The fix starts at the protocol layer

Not another chatbot wrapper. A coordination daemon that sits under your existing harnesses and enforces order: leases, lanes, quorum, proofs.

MACP quorum kernel

Five bounded modes — decision, proposal, quorum, task, handoff. Shared changes need a vote, not luck.

Semantic CRDT

Delta-state registers on AST symbols and contracts. Lamport vector clocks give strong eventual consistency.

Stdio JSON-RPC 2.0 bridge and an A2A 1.0 agent card out of the box. No harness-side SDK to install.

 06

Harness-gated trunk

T0/T1/T2 verification binds base + change hash. Nothing merges until the harness says yes — then CAS advances trunk.

Straight answers

FULL DETAILS IN DOCS.HTML
What is AgentMesh?
A self-hosted coordination layer for AI coding agents. A small hub daemon plus an MCP/A2A bridge run on your machines; harnesses declare intents, work in isolated lanes, vote in MACP sessions, and land changes through a harness-gated trunk. The demo dashboard — the strip board — watches all of it live.
How is it different from worktree orchestrators or vendor-native teams?
Vendor-native teams only work inside one vendor's session. Worktree orchestrators isolate files but leave ports, databases and .env colliding, with no contract or quorum semantics. AgentMesh works at the protocol level: leases with AST collision forecasts, copy-on-write lanes, MACP quorum votes, and a CAS-gated trunk — across vendors and across machines.
Do my API keys leave my machine?
No. Your model keys live in your harnesses' own config, as always. The hub binds to 127.0.0.1 or your LAN, optional bearer-token auth is supported, and the repo, lanes and event log never leave your machines unless you explicitly point them at a remote Git.
Which harnesses work today?
Google Antigravity, OpenAI Codex, Cursor, Claude Code and OpenCode connect via the stdio MCP bridge (JSON-RPC 2.0). The A2A 1.0 gateway covers agents like xAI Grok, and any OpenAI-compatible driver can be registered as a mesh actor. New harnesses need only MCP or A2A — no SDK.
Does it replace Git?
No — it layers above it. MeshVCS lanes are copy-on-write snapshots on top of your working tree, so mesh undo and mesh rewind never rewrite Git history. Trunk is Git's main branch, advanced only through the CAS gate after the verification harness passes.
How do two laptops connect?
On laptop 1 run MESH_HOST=0.0.0.0 node src/hub.mjs (or npx @harshalsp/agentmesh up). On laptop 2 run ./bin/mesh-join http://<LAPTOP_1_IP>:7777 — it tests the connection and wires the MCP config for Cursor, Codex or Claude Code automatically. Works over LAN or Tailscale.
