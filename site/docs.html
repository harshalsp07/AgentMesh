Quickstart — two laptops, under 2 minutes

#quickstart

Two machines edit the exact same repository in real time. One hosts the hub, the other joins over LAN, and both IDEs get mesh tools through MCP.

Step 01 · Laptop A — host

Install and boot the coordination hub (all network interfaces, so Laptop B can reach it):

# any fresh shell
npx @harshalsp/agentmesh up       # hub on :7777 + room key printed
# or, from a clone, LAN mode
MESH_HOST=0.0.0.0 node src/hub.mjs
# note Laptop A's LAN IP, e.g. 192.168.1.50
Step 02 · Laptop B — join

Zero-config join writes the local MCP config and registers presence on the hub:

# from Laptop B (repo cloned anywhere)
./bin/mesh-join http://<LAPTOP-A-IP>:7777
# ✔ hub online (seq, epoch) · ✔ presence registered · ✔ .cursor/mcp.json written
Step 03 · Use it inside any IDE

Reopen your IDE chat and the mesh_* tools appear via MCP — declare before editing, delegate to the other laptop, vote in quorum sessions. Watch it live at http://<LAPTOP-A-IP>:7777 (canvas at /canvas, event stream at /events).

# sanity check on either laptop
node bin/mesh doctor   # ports · node versions · git · driver · board
NOTE Want AgentMesh in an existing repo instead of a clone? Run mesh init <your-repo>: it installs AgentMesh config into the target repo — writes .agents/mcp_config.json and .agents/rules/agentmesh.md, adds .mesh/ to .gitignore, and detects .cursor / .mcp.json / .windsurf configs, adding an agentmesh server entry to each. The AgentMesh dir stays a plain dependency — the hub clones nothing.

Concepts

#concepts

Nine primitives make multi-agent work safe; everything is a view over one event-sourced core (.mesh/ SQLite WAL log).

Lane

A copy-on-write virtual workspace per agent, layered above Git: Agent A never edits the checkout Agent B stands in; each actor drives its own lane lane/<actor> while Git stays the shared source of truth.

node bin/mesh lane antigravity-ui
node bin/mesh diff antigravity-ui

Intent

Intent-before-edit: an agent declares what it is about to touch — paths, symbols, contract effect — before writing code. The hub computes overlaps in milliseconds and warns both sides while the change is still cheap.

mesh_declare_intent({
  goal: "Redesign navbar",
  paths: ["site/**"],
  effect: "additive"              // none | additive | breaking
})

Lease — soft vs hard

Every declared intent carries a lease with an AST collision forecast:

  • Soft lease — an overlap with a neighbor's scope raises a non-blocking OVERLAP warning on both boards; humans or MACP decide who proceeds.
  • Hard lease — an exclusive write barrier; an overlapping write is refused with 409 before any code is touched. Leases sweep automatically: 10 s sweeper, 15 s silence flags an actor away.

Contract — proposal → stable → land

API shapes observed across lanes (routes, params, signatures) become contract nodes with a lifecycle: proposed → diffed against stable → land only after quorum. Ghost clients are detected, deletions are gated, and drift reaches consumers as a tier-1 BREAKING notice on their next pull.

MACP — the 5-mode kernel

Multi-Agent Coordination Protocol: bounded RFC-grade sessions between agents — never a prompt, always a protocol:

  • decision — weighted voting with binding resolution.
  • proposal — 3-round negotiation ladder: scope partitioning → temporal sequencing → human arbitration.
  • quorum — strict threshold gate for schema migrations and contract landings.
  • task — formal bounded work delegation.
  • handoff — capsule state transfer when an agent leaves mid-work.
mesh_propose_contract(title: "Adopt Contract v3 schema",
  mode: "quorum", participants: ["antigravity-ui", "codex-backend"])
mesh_vote(id, vote: "yes", weight, rationale)   # ×2 = quorum met

Integration queue + trunk CAS

Nothing merges to main on vibes. Changesets verify against the exact base_hash + change_hash they were built from: T0 fast gates — syntax, secret scan, boundary policy (<150 ms), T1 npm test, T2 cross-lane contracts. Only then does a compare-and-swap advance the trunk head; a stale base is quarantined, retried (×3), or bisected.

MeshVCS — snapshots, undo, rewind

Every turn of an actor is snapshotted immutably, then undone or rewound without touching shared history — the other lanes never feel it.

node bin/mesh snapshot codex-backend "pre-refactor"
node bin/mesh undo codex-backend               # drop the last turn
node bin/mesh rewind codex-backend --minutes 15

Semantic CRDT — Lamport / LWW

AST symbols, config keys and contract nodes live in a delta-state CRDT on a Lamport vector clock: commutative last-write-wins with actor tie-breaking, so N laptops converge without locks. Only the minimal delta travels the wire; a signature change in one lane reaches every other lane in seconds.

mesh_crdt_set(key: "src/api.ts:port", value: "8080")
mesh_symbols("src/auth.mjs")

Fact sheets — bounded context

Every agent reads the mesh through a fact sheet that is deliberately bounded: 3200-char sheet, 1200-char deltas, 50-message inbox cap, hop limit 3. Context is scoped on purpose — no one agents from a 200k-token kitchen dump, which is both a token budget and a prompt-injection surface reduction.

Tasks — the shared task board

#tasks

Cross-vendor kanban at the event-log layer: a task is a mesh object. Atomic claims — one event, reduced single-threaded by the hub, so two agents racing for task-7 yields exactly one winner. Tasks carry path hints (collision-aware claiming), dependencies (with cycle detection) and WIP limits. Every transition lands in the log; queryable at GET /api/tasks, claimable via MCP:

mesh_task_list(status: "pending")              # pick up work
mesh_task_claim(id: "task-7")                  # atomic; loser gets denied
mesh_task_set(id: "task-7", status: "done")    # unblocks dependents

Conductor — the mesh's own bot

#conductor

A mesh-native bot bundled with the system (mesh bot). Not a model wrapper pretending to run the show — a role lord harnesses drive under enforced protocol. One process, six personalities selected per task:

RoleWhat it doesMesh powers
ScoutWalks the repo, maps modules + contract graph before anyone asksmesh_declare_intent (read-only)
DispatcherSplits a goal into scopes with overlap estimates; opens lanes and tasksintents, /api/tasks
RefereeWatches collisions, drafts negotiation ladders (optionally auto-arbitrates)MACP proposal mode, pins
ReviewerFresh-context review of every landed changeset + drift alertsmesh_pin, T2 hooks
ShepherdNewcomer briefs, standup digests, handoff capsulesmesh brief, digest, capsule
KeeperRepo memory: conventions that worked, "how this repo behaves"mesh memory namespace

Budgeted autonomy: every run declares token/coin plus wall-clock budget up front ("will cost ≈ $0.4 · 8 tasks"), enforced by policy, capped hard. Rehearse before you spend:

mesh bot run "split auth refactor across 2 agents" --dry   # plan + price, no spend
mesh bot run "..."                        # real run under budget

Every claim the bot makes is a DAG node referencing the intent/event behind it — visible provenance. Safe default: write-lane + declared intents for anything it touches; it never merges to trunk without quorum of its own.

Memory — repo memory for every agent

#memory

The Keeper role backends a key-value memory on the same event log: conventions that worked, de-facto truths, "how this repo behaves". Bounded by design — a char-budgeted .mesh/memory.md plus a keyword index, portable (copy the .mesh dir, or read it from a fresh clone).

mesh memory set "migrations" "events.jsonl → SQLite WAL only past 100k"
mesh memory get "migrations"              # → what an earlier session learned

Exposed to any harness via mesh_memory_set / mesh_memory_get, so laptop 2 inherits what laptop 1 learned yesterday.

Services — ports and .env owned like files

#services

Worktrees never solved the "both agents bind dev-port 3000" fight. Intents carry a service claim: services:["dev-port:3000","db:shared"] — a service collision hits the same tier as a path overlap. Shared .env rides along: lanes inherit it from trunk, and a changed key is a contract node with real breaking-change notices.

mesh_declare_intent({
  goal: "Build checkout flow",
  paths: ["apps/shop/**"],
  services: ["dev-port:5173"]       # nobody else binds 5173 this turn
})

Writing an intent by hand

curl -X POST http://127.0.0.1:7777/cmd \
  -H "content-type: application/json" \
  -H "authorization: Bearer $MESH_TOKEN" \
  -d '{"actor":"codex-backend","kind":"intent.declare",
      "payload":{"goal":"Patch UI bug","paths":["site/**"],
                 "effect":"additive"}}'
AUTH Writes authenticate with Bearer capability tokens per actor: mint one with mesh token <actor> — actor, scope and 8-hour expiry, signed by the hub's ed25519 key. Scopes limit what a token may write (intent.declare ≠ request ≠ pin). Enforcement is auto-armed once keys exist (mesh up generates them); a key-less hub stays open for local dev only. Missing/expired → 401; token-actor ≠ body actor → 403. See Security model.

Security model

#security

Premise: every agent is untrusted by default — even yours. Safety is enforced at the boundary, never requested via prompt.

  • Boundary enforcement over prompts — deny-list + approval mesh run shims on PATH (a denied real binary never execs: exit 126/125), plus leases, policy and quorum gates in the hub. A rogue harness can ask loudly; it still hits the wall.
  • ed25519 capability auth — actor-bound, scoped tokens, ≤8 h expiry; impersonation fails with 403 (token actor must equal body actor).
  • Token rotation + revocation — mesh keygen rotates the hub key; reissue with mesh token <actor>; revoke one credential with mesh token revoke <jti>. Tokens are stateless (max 8 h life), so a restart plus stop-issuing cuts off everything at once.
  • Human overrides agent leases — approvals collect in a human inbox; a human response wins over agent-side quorum. A hallucinated approval is data, never fact.
  • Audit export — mesh audit export ships the signed, hash-chained trail; /verify proves log integrity under SQLite WAL.
  • DoS budgeting — 100 writes/min/actor (429), 1 MB bodies (413), retry cap 3, circuit breaker 20/min.
  • Degrade to plain git — if the hub dies mid-sprint, you still hold an ordinary clone. Eject branches with mesh eject, restore bundles with mesh recover. No lock-in.
  • No vendor cloud — hub, keys, memory and audit live in the repo's .mesh/ and the SQLite file. LAN or VPN only; the hub warns when bound non-loopback without auth.

Troubleshooting

#troubleshooting

First stop: mesh doctor

Diagnoses ports, node/git versions, driver, network shape and board files in one pass. If pins or status look stale but writes still land, suspect a stale canvas tab; doctor resets the baseline.

node bin/mesh doctor

Port busy (7777)

Another hub (or a zombie from a crashed session) is holding the port. Kill it, or run the hub on another port.

# mac / linux
lsof -ti :7777 | xargs kill -9
# windows
netstat -ano | findstr :7777
taskkill /F /PID <pid>          # /T too if the node froze with children

401 on every write

Your capability token expired (8 h) or was rotated (mesh keygen). Mint a fresh one and re-export it — the bridge reads MESH_TOKEN, curl reads the authorization header.

mesh token codex-backend --ttl 8      # fresh ed25519-signed credential
export MESH_TOKEN=<paste>             # used by bin/mesh + bridge

Notes on node src/hub.mjs

  • Default bind is loopback; only MESH_HOST=0.0.0.0 exposes it to the LAN — and it still warns when bound non-loopback without auth.
  • 7781/7782 belong to npm test — don't park the hub there.
  • SIGINT/SIGTERM checkpoint the SQLite DB before exit — a clean, if slow, shutdown; double Ctrl-C is not faster.

Windows notes

  • taskkill cleanup — a killed terminal sometimes leaks node.exe; taskkill /F /IM node.exe clears the deck (it will kill every node process on the box).
  • PATHEXT shims — mesh run emits shim executables as *.cmd wrappers so Windows PATH resolution (via PATHEXT) finds them; if a 126/125 exit appears, check the shim dir is first on PATH.

Hub unreachable from laptop B

  • Laptop A must run with MESH_HOST=0.0.0.0 — a loopback bind never accepts LAN joins.
  • Use laptop A's LAN IP (ipconfig / ip a), e.g. 192.168.x.x — not the loopback.
  • Test first: curl http://<LAPTOP-A-IP>:7777/health from laptop B, then ./bin/mesh-join ….
  • Still refused: LAN firewall or guest-Wi-Fi AP isolation — or just join over VPN/Tailscale.
