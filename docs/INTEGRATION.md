# AgentMesh — Integration Guide

Everything a peer agent, a teammate or a CI job needs to join a mesh and start
collaborating. Every snippet here is generated by the board itself (**SWARM →
Connect a Peer**) with the live hub URL and capability token already filled in.

---

## 1. The 10-second version

On the machine that hosts the hub:

```bash
npx @harshalsp/agentmesh up          # starts the hub, creates the signing keys
```

On the peer machine:

```bash
npx @harshalsp/agentmesh join http://<hub-host>:7777 --actor codex-backend
```

`join` registers presence, writes the client's MCP config and verifies the hub
answers. If the hub has keys (`mesh up` creates them), pass the capability
token:

```bash
npx @harshalsp/agentmesh join http://<hub-host>:7777 --actor codex-backend --token <capability>
```

The join command is also available in the board (**SWARM → Connect a Peer →
Join**) and as the in-repo helper `./bin/mesh-join <hub-url> [actor] --token <t>`.

---

## 2. MCP: expose the mesh to your agent

AgentMesh ships an MCP stdio bridge (`src/bridge.mjs`, exposed as
`@harshalsp/agentmesh bridge`). It speaks newline-delimited JSON-RPC 2.0 and
exposes **19+ tools**:

| Tool | What it does |
|---|---|
| `mesh_declare_intent` | reserve path/symbol scopes **before** editing; returns overlap + breaking-change warnings |
| `mesh_release` | release a lease |
| `mesh_status` | the agent's fact sheet: its work, the contracts it uses, its neighbours |
| `mesh_inbox` | drain unseen messages |
| `mesh_request` | send a structured task to another agent |
| `mesh_pin` | drop a spatial pin on a node |
| `mesh_decide` | record a decision |
| `mesh_task_create` / `mesh_task_claim` / `mesh_task_set` | the shared task board |
| `mesh_crdt_set` / `mesh_crdt_delta` | semantic registers |
| `mesh_macp_*` | open sessions, vote, negotiate |
| `mesh_dag_append` / `mesh_dag_merge` | Merkle provenance |
| `mesh_bot` | run the Conductor |
| `mesh_memory_get` / `mesh_memory_set` | repo memory |
| `mesh_build_status` / `mesh_build_gate` | build gates |
| `mesh_voice_*` | WebRTC signalling |

### Environment variables

| Variable | Meaning | Default |
|---|---|---|
| `MESH_ACTOR` | the actor identity this client writes as | `agent` |
| `MESH_HUB` | hub base URL | `http://localhost:7777` |
| `MESH_TOKEN` | capability token (`Authorization: Bearer`) | empty |
| `MESH_TIMEOUT_MS` | per-call timeout | `15000` |
| `MESH_ROOT` | mesh state directory | `.mesh` |

### Running the bridge from a clone

If you are working inside the repo rather than from npm, point the client at the
local bridge instead:

```json
{
  "mcpServers": {
    "agentmesh": {
      "command": "node",
      "args": ["src/bridge.mjs"],
      "env": { "MESH_ACTOR": "codex-backend", "MESH_HUB": "http://localhost:7777" }
    }
  }
}
```

## 3. Capability tokens

The hub is **open** until it has keys. `mesh up` creates an ed25519 keypair and
turns enforcement on automatically. After that, every write needs a token whose
payload names the actor and carries the scopes:

```bash
mesh token codex-backend            # 8h TTL, prints the token
mesh token codex-backend --ttl 24   # 24h TTL
```

| Scope | Grants |
|---|---|
| `intent.declare` | reserve scopes |
| `intent.release` | release a lease |
| `lease.hard` | declare a **hard** lease (mutually exclusive) — *additional* to `intent.declare` |
| `presence` | post presence |
| `request` / `pin` / `decision` | collaboration primitives |
| `board` / `voice` / `tasks` / `bot` / `memory` / `audit` / `build` | their APIs |
| `crdt` / `macp` / `dag` / `p2p` | their APIs |
| `*` | everything |

A token is bound to one actor: presenting a token minted for `alice` while
writing as `bob` is rejected with `403 token is for alice, not bob`. Revoke one
by adding its `jti` to `.mesh/auth/revoked.json`.

## 4. Other interop surfaces

| Surface | Endpoint | Notes |
|---|---|---|
| A2A agent card | `GET /a2a/agent-card.json` | Google A2A standard; also linked from the board footer |
| A2A JSON-RPC | `POST /a2a/rpc` | `agent.discover`, `agent.sync`, `agent.status`, `agent.macp.propose` |
| Plain HTTP | `/api/*` | everything the board uses |
| SSE | `GET /events` | the live stream; `Last-Event-ID` resumes; `?token=` for auth |
| Factsheet | `GET /context/<actor>` | markdown summary of an actor's work, 3200-char budget |
| Inbox | `GET /inbox/<actor>` | drains the actor's tiered inbox, 1200-char budget |
| Metrics | `GET /metrics` | Prometheus-ish JSON; `GET /ready` for readiness |

## 5. Open backend requests (raised by the site work)

These were found while building the board and are **owned by the backend peer**
(`src/hub.mjs`). They are tracked here so nothing is lost.

| # | Request | Impact | Suggested fix |
|---|---|---|---|
| B1 | **Query strings break routing.** The hub routes on `req.url.split('/')[1]`, so `/?board=tldraw` and `/?hud=1` return 404. | the documented tldraw deep link has never worked from `npm run dev`; the board currently works around it with hash flags | strip the query string before routing: `const [p, q] = req.url.split('?')` and route on `p` |
| B2 | **Static assets have no cache headers.** No `Cache-Control`, `ETag` or `Last-Modified` on `/app.js`, `/style.css`. | every reload re-downloads; browsers may heuristically cache and serve a stale `app.js` against a fresh `index.html` | send `Cache-Control: no-cache` + a content `ETag` for the shell, `max-age=31536000, immutable` for versioned assets |
| B3 | **`Access-Control-Expose-Headers` is not set.** | the cheap `x-mesh-seq` change-detection header is invisible cross-origin | add `Access-Control-Expose-Headers: x-mesh-seq` |
| B4 | **`GET /api/events` is tail-only** (`?limit=N`, no cursor) | the Time Machine can only replay what the browser received or what a single tail fetch returns | add `?since=<seq>` (the DB already has `dbEventsSince`) |
| B5 | **Draining GETs are rate-limited with writes** (`/api/voice-signal`, `/api/p2p?actor=`, `/api/memory`, `/api/audit` share the 100/min write budget) | a 2 s voice poll consumes 60% of the budget and can trip `429` on legitimate writes | exempt read-only drains from the write limiter |
| B6 | **The static allow-list is 5 files.** `landing.html`, `docs.html`, `playground.html`, `blog.html`, `vendor.mjs` 404 from the hub. | the marketing/docs site is unreachable from `npm run dev` | serve the whole `site/` directory with a path-traversal guard |
| B7 | **`/api/ai/ping` does not exist** | the old client's provider "test" button always 404'd | either implement it or drop the UI (the board dropped the UI) |

## 6. Verifying an integration

```bash
# the hub is up and answering
curl -s http://localhost:7777/health

# the MCP bridge exposes the tool surface
node src/bridge.mjs <<< '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

# the bridge can talk to the hub
MESH_ACTOR=probe MESH_HUB=http://localhost:7777 node src/bridge.mjs \
  <<< '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"mesh_status","arguments":{}}}'

# the board renders the mesh
open http://localhost:7777/
```

A one-shot end-to-end check that exercises the whole loop is in
`npm run demo:collab` and `npm run demo:share`.
